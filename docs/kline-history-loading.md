# K 线历史加载与缺口复核

本文定义图表历史读取、向前续页和可见缺口复核的运行时状态机。数据来源、Bar 生命周期和同源边界仍以 `data-semantics.md` 为准。

## 1. 本地读取

1. 首屏通过 `GET /api/bars/{code}` 读取最新 500 根周期 Bar，并立即绘制。
2. 响应同时返回服务端生成的 `next_cursor` 和仅供诊断的 `next_before`。浏览器只保存并回传不透明游标，不能从 Bar 时间重建、比较或修改游标。
3. 用户接受的左缘需求只发送一次 `POST /api/bars/{code}/history?cursor=...&count_back=...`。服务端先读当前游标之前的本地页；本地已满足时不访问上游。
4. 历史命令在需要时执行一个受限的同源传输步骤、增量物化目标周期并直接返回规范页；浏览器不再串联“本地 GET → 多个分钟回补 POST → prepare POST → 再 GET”。
5. 历史前插后按新增逻辑点数平移可见区；用户跟随最新价时仍保持在尾部。

1 分钟以上的派生周期仍以同源 1 分钟 Bar 为事实底座。物化结果保存在 `derived_period_bars`，进度保存在 `period_bar_materializations`。物化页的排他游标取最早周期桶中第一根事实 Bar 的时间，而不是周期桶的显示开盘时间；这保证日、周、月等未完整最老桶也能严格向前推进。重复命令只处理事实层新增或修订的桶；若变化只发生在当前实时尾部，GET 通过 PostgreSQL 范围聚合只读重算受影响桶并覆盖到已物化页，不再把整月、整季或整年的分钟 Bar 分页搬回应用进程。更早事实到达时会重新打开原先的本地耗尽标记，使后续命令可以继续向前扩展。

## 2. 持续历史需求

历史需求在以下任一条件成立时激活：

- 用户拖动或缩放到当前序列左边缘；
- 当前完整已加载序列仍不足以覆盖可见窗口。

需求一旦激活，即使已有历史命令占用加载锁也必须保留。锁释放或数据前插后重新评估；若已经离开左缘则结束需求。服务端游标已经推进、但还没有形成新逻辑 Bar 的响应会完成当前浏览器需求；React 重绘、同一长周期桶扩大或“全部已加载数据仍可见”不能自动重新激活它。用户下一次真实拖动或缩放仍可用服务端返回的新游标提交下一步，因此一个动作只对应一个普通历史命令。

`count_back` 始终表示逻辑 Bar 数，取可见 Bar 数、默认 240 根和已启用指标最大预热长度三者的最大值，与分钟、小时、周或年周期无关。周期到事实分钟范围的换算以及单次最多 10000 分钟的传输限制只存在于服务端；浏览器不得把 240 根周 K 换算成数百万分钟并拆成数百个请求。

分时和所有 K 线使用同一个历史协调器及游标契约。能力差异只通过状态表达：分时当前读取本机已经记录的 1 秒 Bar；本地 1 秒页结束后返回 `source_status=unsupported`，不能把上游 1 分钟历史虚构成逐秒轨迹。

响应把本地状态与来源状态分开：`local_status` 只有 `ready/empty`；`source_status` 为 `available/deferred/exhausted/unsupported`。上游窗口成功但没有新增 Bar 时，只有响应中的确认覆盖边界才能生成新游标。`deferred` 保留当前游标并等待 `retry_after`，`exhausted` 或 `unsupported` 正常结束当前需求。一个周末、物化器读到本地分钟库底部或任意数量的连续空窗口都不能推导来源历史边界；只有提供方明确返回并写入 `realtime_bar_series_state.history_floor` 的证据才是权威停止点。后续相同底部请求由统一数据源状态直接返回 `exhausted`，不再访问上游。

## 3. 可见缺口精确复核

固定周期图表使用市场时段识别缺口。只有同时满足以下条件才调用 `revalidate=true`：

- 缺口位于两个真实 Bar 之间；
- 两个 Bar 属于同一个已知交易时段；
- 缺口进入当前可见逻辑区间；
- 同一来源、品种、起点、分钟数和证据版本不在复核冷却期内。

每次可见范围变化最多发起四个精确复核。跨会话、维护、周末和其他计划休市不进入该流程。复核仍使用合约当前绑定来源的历史能力，按最多 10000 分钟切片；完成后重新读取对应周期页并按 revision/state 合并。

前端只去重在途请求并遵守响应冷却；证据版本变化或冷却结束后可以再次提交同一个精确窗口。后端仍是最终裁决者：普通覆盖不能阻止 `revalidate`，但相同证据版本和范围在冷却期内返回 `deferred`，不会再次访问上游。

### 3.1 金十可变历史文件与 CDN

金十当前交易日历史文件会在相同文件标识下继续追加，文件服务同时声明 `Cache-Control: max-age=600`。因此，文件名本身不能作为永久缓存版本：manifest 已推进时，普通 URL 可能仍命中条数更少的 CDN 旧文件。

- 下载请求以 manifest 的 `record_count + end_timestamp` 组成稳定版本参数；manifest 版本推进时形成新的 CDN 缓存键。
- 本地文件缓存只有在 manifest 声明的 `[start_timestamp, end_timestamp]` 内覆盖条数等于 `record_count` 时才可复用，否则必须重新下载。
- 若稳定版本请求仍未覆盖 manifest 声明区间，后端使用唯一刷新参数再下载一次；第二次仍不足才报告协议错误，不把瞬时 CDN 旧副本交给页面重试。
- 下载文件可以包含 `end_timestamp` 之后后来追加的真实 Bar，但声明区间内不得少行；区间内条数不符仍然硬失败并显示期望、实际、下载总数和边界。
- 该规则只处理同一官方文件的追加与缓存一致性，不放宽 GZip 结构、OHLC、时间戳和来源校验，也不生成缺失价格。

## 4. 回补结果与权威状态

| 状态 | 含义 | 页面行为 |
| --- | --- | --- |
| `cached` | 请求范围已在 PostgreSQL 永久覆盖中 | 重新读取本地页；只有确认边界可推进 |
| `joined` | 与完全相同的在途请求合并 | 读取合并任务结果，不重复访问上游 |
| `fetched` | 本次取得并原子写入了 Bar | 重新读取本地页并保持视窗前插 |
| `advanced` | 上游成功检查，但该范围没有 Bar | 按 `covered_start` 向前推进，不猜测下界 |
| `exhausted` | 已到达明确的 `history_floor` | 正常结束当前需求，不显示边界提示 |
| `deferred` | 处于软尾部冷却或失败退避 | 保留左缘需求，到 `retry_after` 再评估 |

`authoritative_through` 是排他权威时刻，边界本身不属于永久确认范围。`latest_authoritative_open_time` 单独记录最后一根权威 Bar；二者不能互相推导。永久覆盖只写到成功检查范围与 `authoritative_through` 的较早者。其后的当前可变尾部只保存 `tail_checked_through / tail_checked_at` 软检查；冷却内不重复请求，实时权威水位推进后可立即再查。`history_floor` 只来自明确上游证据。

原始 Candle、统一 Bar、覆盖范围和上述序列状态在同一个短 PostgreSQL 事务中提交。网络请求不占用该事务；提交失败时不发布内存历史，也不写任何覆盖或水位。

## 5. 错误与停止状态

- 最新页失败：主图显示阻断错误和重试入口。
- 本地后台分页失败：保留已绘制数据，并显示非阻断历史错误。
- 绑定来源的历史回补未配置：继续读完已有同源本地 Bar，随后按正常历史边界结束；不调用上游，也不显示失败。
- 更早窗口失败：结束当前自动需求并显示失败原因。
- 精确复核仍返回零行或无法生成目标周期 Bar：保留空白，不制造价格；成功空响应属于正常证据，不显示错误。
- 来源或周期切换：清空旧游标、复核去重集合和旧请求结果。
- 鉴权失败：重新解析一次客户端会话并只重试一次；仍失败则进入指数退避。失败、取消或过期请求结果都不能合并到新数据集。
- 加载状态只有在历史命令超过 150ms 后才显示；快速本地命中、正常空窗和明确耗尽不闪烁、不显示额外边界消息。

## 6. 传输边界

| 接口/环节 | 上限 |
| --- | ---: |
| 图表 Bar API `page_size` | 10000 |
| 历史命令 `count_back` | 10000 个逻辑 Bar |
| 分时事件 API `page_size` | 20000 |
| 单个服务端上游传输步骤 | 10000 分钟 |
| 单次可见区缺口调度 | 4 段 |
| 业务批次 Bar 数 | `max(可见 Bar, 240, 已启用指标最大预热)` |

传输上限不是业务历史截止点；后续被接受的左缘需求必须继续使用服务端游标，不能回退为浏览器分钟窗口循环。
