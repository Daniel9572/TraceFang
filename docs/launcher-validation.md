# 跨平台统一启动入口与验证

> 最新需求已改为应用窗口持有服务生命周期。下方常驻后台启动耗时是前一阶段结果，
> 不能当作新应用窗口模式的验收结果。

## 应用窗口模式：实现及验证

新增 macOS AppKit 控制窗口与 Windows WPF 控制窗口，共用 Python `session`：
取得独占应用锁 → 启动服务 → 就绪通知 → 等待窗口管道关闭 → 停止后端及项目容器。
第二个会话不能停止第一个；启动异常仍执行清理；停止未确认时不返回成功。窗口关闭
和退出菜单都走停止流程，不将退出按钮当作后台隐藏按钮。关闭浏览器页仍只是关闭展示页。

macOS 服务注册从 LaunchAgents 迁入 Application Support，保留同一安装版本，避免登录
时无应用窗口自行启动。Windows 任务不再配置登录触发器。旧终端启动入口作为显式维护
工具保留，其生命周期不同；外层日常入口已替换为 `TraceFang.app`。

本机 Swift 原生应用编译通过，现有服务相关 19 项和新增应用会话 5 项单测通过。
首次启动应用时，macOS TCC 日志明确记录等待 DocumentsFolder 授权；子进程阻塞在
Python 初始化读取运行环境阶段，尚未执行会话逻辑。因此初次点击停止未完成清理，
不能宣称应用关闭、异常退出清理或效能已经实机通过。需用户允许新应用读取项目所在
文稿文件夹后继续验收；没有改写隐私数据库、授予完全磁盘权限或规避权限检查。
Windows WPF/VBS 新入口未执行实机验证。此前 PowerShell 解析结果不覆盖这份新增窗口脚本。

### 授权后的复核与提交前检查

随后授权阻塞已解除，原生窗口实际显示服务运行中。点击窗口红色关闭按钮后，窗口先
显示正在停止，再退出；确认应用与会话进程均已结束，8000 端口无监听，本项目两个
容器均未运行。这次只验证正常关闭，不等同于应用崩溃清理或 Windows 实机验收。

启动成功后残留的权限等待说明已修正。另补上重复应用的专用退出状态：不能取得服务
归属时，窗口只允许关闭自己，不提供可能误停其他窗口服务的重试按钮。
修正后 Swift 应用再次编译通过；未重复更改系统文件夹授权。六份 PowerShell 脚本
（含新增应用窗口脚本）解析通过，WPF 窗口与 VBS 引导仍未在 Windows 上执行。

提交前回归排除上述缺失 HistData 样本组后，326 项中 318 项通过、8 项条件跳过。
运行中单次系统快照：原生窗口 RSS 约 61.44 MiB，会话进程约 13.42 MiB，两者 CPU
报告值均为 0.0%；这不是长期稳态或峰值测量，也不是跨平台资源对比。

扩大回归明确排除缺少本地 HistData 样本的测试组后，325 项中 317 项通过、8 项条件跳过；
代码规范和差异检查通过。测试期间已使用维护入口正常停止后端与两个项目容器，确认
应用端口无监听；这不是新窗口停止行为的验收替代。系统日志显示旧编译版本的文件夹
授权已获响应，但本地重编译会改变代码签名，新版本再次等待授权；没有自动点击允许。

此模式新增一个原生控制窗口与一个等待管道的轻量会话进程，二者只在应用使用期间存在；
没有引入 Electron、浏览器内核包或第三方 Python 依赖。新增资源开销尚未实测，不能沿用
前一阶段“无常驻启动器进程”的结论。Windows 窗口用定时器读取子进程消息，亦待实测。

## 组件边界

React 前端在浏览器执行；Python 后端承载接口、业务和采集模块；PostgreSQL 与
NATS/JetStream 是两个独立容器。前端产物由后端提供下载，不改变前端的逻辑归属。
macOS 托管后端，Docker 托管容器。启动器是一次性管理程序，不增加常驻进程或框架。

| 操作与状态 | 行为 |
| --- | --- |
| start：已经就绪 | 只读本机 readiness、检查页面并打开浏览器 |
| start：未运行 | 启用系统注册；后端启动前确保 Docker 与两个容器就绪 |
| start：正在启动 | 通过文件锁等待正在执行的启动；复用已加载进程 |
| start：加载但不健康 | 等待当前尝试，仍失败则重启一次；超时卸载本次运行并返回错误 |
| update / install | 准备独立候选版本，安装依赖、导入检查，通过后切换注册并检查就绪 |
| update：新版本激活失败 | 尝试恢复旧注册及之前运行的版本；保留数据 |
| stop | 等旧进程退出，再停本项目两个容器；保留安装并禁用登录自启 |
| restart | 重启已安装版本，不部署工作区代码 |
| uninstall | 停止并移除托管注册；保留运行目录及数据 |

新版本准备失败不停止当前服务。上一运行版本保留；这不是数据库事务回滚机制，不承诺
未来破坏性数据库迁移可自动撤销。旧运行目录可能占用磁盘，当前不自动清理用户已有版本。
普通启动不执行 Git 同步。AGENTS.md 仍只记录代码目录与远端仓库位置。

`/api/ready` 只读取本机数据库写入器状态、采集管理器存在状态和 NATS 连接状态；前端
页面另行检查。它不调用上游，也不保证市场正在报价。数据库健康度沿用已有写入器观测，
不额外逐次执行 SQL 探测。上游状态仍由已有健康接口和页面显示。

## 可复现实验

工作目录为代码仓库，执行：

```sh
.venv/bin/python scripts/benchmark-launcher.py --cold-runs 10 --recovery --idle-seconds 600
```

默认仅做 30 次顺序启动、10 次并发启动和既有 WebSocket 连通性验证。
`--cold-runs` 会反复停止项目服务，`--recovery` 向系统注册的本项目后端发送终止信号；
两项会造成测试期间采集中断，宜在维护时间执行。脚本不会退出整个 Docker Desktop。
资源观察期间不主动操作前端，现有采集任务仍运行，不代表零业务负载。

启动耗时从调用入口到入口返回，不包含浏览器绘制。P95 使用最近秩法。
macOS 资源采样使用系统进程统计，CPU 百分比是系统报告值，并非精确的逐区间 CPU 计时。
Windows 采样通过系统进程查询获取累计 CPU 时间和工作集，计算采样区间 CPU 百分比；
两平台 CPU 口径不同，不直接横向比较。采样查询是临时测试进程，不是常驻应用组件。

## 本机结果（2026-09-05）

| 项目 | 结果 |
| --- | --- |
| 修改前：已运行时再次启动 | 24.33 秒，单次基线；发生重新部署和后端重启 |
| 修改后：顺序启动 30 次 | 中位 0.161 秒；P95 0.217 秒；最大 0.277 秒 |
| 修改后：并发启动 10 次 | 中位 0.564 秒；最大 1.050 秒；后端 PID 不变 |
| 既有页面连接 | 40 次启动后原 WebSocket 仍响应 ping；后端 PID 不变 |
| 冷启动 10 次（Docker 已运行） | 中位 14.238 秒；最大 / P95 18.754 秒；全部成功 |
| 自动恢复 | 本项目后端收到终止信号后，9.052 秒内由系统重新启动并就绪 |
| 10 分钟资源观察 | 60 次采样，后端 PID 不变；CPU 报告均值 3.59%；RSS 初始 / 峰值 133.66 MiB，末值 49.25 MiB |

基线只有一次，不能据此声称统计意义上的固定加速倍数。没有测量真实浏览器首屏绘制
或上游行情端到端延迟；WebSocket 实验只证明启动未替换进程或切断已有连接。
没有实测退出整个 Docker Desktop 后的冷启动，以免影响其他容器；依赖就绪等待有超时。
资源采样从恢复后开始，包含初始化内存回落，不代表长期稳态上限。没有旧版本同负载
资源对照，不能据此声称后端资源消耗较旧版下降。启动器在每次操作结束后退出，
实验脚本也随观察结束退出；没有增加常驻管理服务。

最终运行包复验（增加退出清理时间并移除开发依赖后）：顺序启动 30 次中位 0.077 秒、
P95 0.098 秒、最大 0.106 秒；并发 10 次最大 0.905 秒，后端 PID 及既有 WebSocket
连接保持。完整停止后启动再验一次为 13.279 秒；自动恢复再验一次为 9.891 秒。
十分钟资源观察针对前一改造运行包，最终包仅重复上述启动和恢复测试；不同批次的时间
波动不能全部归因于代码变更。最终包仍沿用同一后端与基础设施，未引入新的运行依赖。

首次冷启动试验暴露了旧进程尚未退出就停止依赖的时序问题。入口已改为确认旧 PID 退出
后再操作容器，随后十轮通过。后端退出增加有界的请求清理时间，系统托管给予其清理窗口。

定向回归：59 项，57 项通过、2 项按既有条件跳过；包括 readiness、更新回退、锁释放、
端口保护、行情路由、观察列表、采集、消息帧、专家接口。更新回退目前是故障注入单测，
不等价于实机演练所有依赖损坏场景。

## Windows 共用入口的验证边界

Windows 入口调用相同 Python 编排逻辑，仅系统任务、文件锁、数据目录、浏览器打开和
后台进程入口按平台适配。旧 PowerShell 启动流程已替换为共用入口转发。

- 共用及 Windows 适配回归共 64 项：62 项通过、2 项条件跳过。
- 使用校验过官方 SHA-256 的临时 PowerShell 7.5.10 执行五份脚本的语法解析，全部通过。
- 在隔离目录实际执行参数转发，确认启动和更新参数不丢失；执行两次配置补齐，确认
  原配置保留、自定义消息端口保留，消息地址仅补写一次。
- Python wheel 构建通过，确认 Windows 任务脚本包含在安装包中。
- 以上 PowerShell 执行环境为 macOS，不能证明 Windows COM 任务注册有效；未执行
  Windows 实机关闭窗口、注销 / 登录、任务崩溃恢复或性能实验。PowerShell 5.1 亦未实测。

任务使用当前用户交互令牌，符合 [Microsoft 的注册接口说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskfolder-registertaskdefinition)。
失败重试最小间隔为一分钟，配置三次，依据 [RestartInterval 官方约束](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-restartinterval)；
重复任务使用 [IgnoreNew 策略](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-multipleinstancespolicy-settingstype-element)。
采用这些设置的代码已实现，实际系统行为仍需 Windows 验收。
