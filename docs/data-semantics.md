# 数据语义基线

本文是当前版本的数据语义唯一基线。其他设计文档、代码命名和界面文案都必须服从本文；出现冲突时，以本文为准。

## 1. 实时数据源

“实时数据源”是用户可选择、合约可绑定的最小完整数据产品。一个可用的实时数据源必须同时提供：

- `quote`：当前报价快照与连续报价事件；
- `kline`：按周期组织的开、高、低、收数据，既包括当前正在生长的柱，也包括该来源能够提供的过去柱。

只提供 `quote` 或只提供 `kline` 的连接不构成完整实时数据源，只能作为实时数据源内部的采集通道或能力组件。实时数据源可以由一个或多个内部通道组成，但内部拓扑不是用户契约，也不能作为合约的独立可选项。

所有实时数据源必须进入同一条业务处理链：`供应商协议 -> 通道适配器 -> QuoteEvent/BarEvent -> 通用 Bar 状态机 -> 本地持久化 -> REST/WebSocket -> 图表`。供应商协议号、字段差异和传输方式只能出现在通道适配器与数据驱动的来源契约中；应用服务、数据库投影和前端不得按供应商名称编写 K 线合并特例。

应用层派生观察值不是新的实时数据源，也不是交易所原生合约。它由已经绑定同一完整实时数据源的多个直连品种计算，只能公开当前推导确实支持的字段与时间范围。界面必须明确标记“换算”及公式来源；不能把派生值包装成另一家交易所的原生报价，也不能为补齐图表而伪造历史 OHLC。

## 2. 历史数据

“历史数据”描述时间范围，不描述数据结构：凡发生在当前时刻之前的数据都属于历史数据。它可以包含报价事件、报价快照、K 线及未来增加的其他行情字段；不能把“历史数据”当作“K 线”的同义词。

当前版本冻结独立的全局历史数据治理。冻结期间：

- 不生成或查询跨来源的全局标准序列；
- 不做多源共识、跨源补缺、免费源优先回填或静默替换；
- 原有 `standard_candles`、`candle_validation_results` 和 `history` 治理结构只作为兼容/研究资产保留，不进入运行时读取或写入链路。

## 3. 合约绑定与同源边界

- 每个合约在任一时刻只能绑定一个实时数据源，数据库以合约唯一约束保证这一点。
- 报价、当前 K 线、过去 K 线、分时和状态全部服从该合约的同一个绑定。
- 切换实时数据源是原子替换；切换后必须清空旧源的页面事件与 K 线缓存，并从新源重新读取。
- 一个来源不可用时报告停滞或缺失，不回退到其他来源。
- 同一供应商的不同接口或接入方式仍是不同采集通道。只有在一个实时数据源的固定内部组成中明确声明后，才能协作生成该实时数据源的结果；原始证据仍按真实通道隔离保存。

### 3.1 品种目录与观察列表

- 品种目录描述应用当前能够展示的全部直连品种与派生观察值；观察列表只保存用户选择持续关注的目录项，两者不能再使用同一份硬编码数组。
- 当前不做品种分类。侧边栏只显示观察列表，管理抽屉从完整目录中搜索、添加或移除品种。
- 观察列表保存在 PostgreSQL，首次使用默认加入 `XAUUSD`、`XAGUSD`、`AU8888`、`AG8888`、`AU2610`、`AG2706`、`USDIND`、`BRN0Y`、`SHCOMP` 和 `IXIC`；为保持主图始终有明确上下文，当前至少保留一个品种。
- 上游实时订阅由观察列表驱动，而不是由浏览器是否打开决定。移除直连品种后，若它仍是某个已观察派生值的计算依赖，后端继续保持该依赖订阅，但不在侧边栏重复显示。

### 3.2 人民币金价换算

`USDCNH` 是金十实时推送中的独立直连外汇品种，表示 1 美元兑换多少离岸人民币。它可以单独加入观察列表。

`XAUCNHG` 显示“国际金(人民币/克)”，计算为：

`XAUUSD(美元/金衡盎司) × USDCNH(离岸人民币/美元) ÷ 31.1034768(克/金衡盎司)`

- `31.1034768` 是 1 金衡盎司对应的克数，不是接口参数或经验系数。
- 两条腿都使用 `jin10_web` 的最新实时事件；任一腿缺失或过期时，不发布新的有效换算价。
- 涨跌额与涨跌幅由两条腿各自的前值共同重建后再计算，不能只把黄金美元涨跌乘一次当前汇率。
- 当前只从同步到达的派生报价生成实时分钟线，不提供历史回补。因为两条独立分钟 OHLC 的最高/最低发生时点未知，直接相乘不能得到真实的历史合成 OHLC。
- 该值是国际现货金按离岸人民币换算的参考观察值，不得命名为上海金、上金所金价或人民币在岸成交价。

## 4. 当前 K 线与过去 K 线

- `QuoteEvent` 和 `BarEvent` 都必须携带逻辑实时数据源、真实证据通道、品种、来源时间、接收时间以及可用的上游序号。Provider 只负责协议解析和标准化事件，不在内部用报价维护另一套业务分钟线。
- 每根 Bar 以 `(实时数据源, 品种, 周期, open_time)` 为唯一业务状态，生命周期只能是 `provisional_quote -> provisional_authoritative -> final`。报价可以创建或生长当前临时柱；权威 Bar 更新以完整 OHLCV 校准临时柱；已完成柱拒绝报价改写。
- 不同来源如何确认收盘由 `RealtimeBarContract` 声明，例如显式完成标记、下一根权威 Bar 水位线或历史文件确认。业务状态机只执行契约，不判断供应商名称或协议号。
- 同源权威通道对已完成柱给出更高修订时，可以受控替换 OHLCV 并递增 `revision`；乱序、降级状态和报价对完成柱的修改必须拒绝。`state`、`revision`、`finalized_at` 与真实 `evidence_channel_id` 必须持久化，重启后恢复同一状态。
- 当前柱只能由绑定实时数据源的同源 K 线状态和同源报价事件更新。
- 新周期的第一笔同源报价决定新柱的初始 `open/high/low/close`；上一根已收盘柱的 `close` 不能被当作新柱的 `open`。
- 同一周期内收到的每一笔有效报价都参与 `high/low/close` 生长，不因源时间只有秒级精度而丢弃中间帧。
- 分时的业务数据是逐笔 `QuoteSample` 事件序列，不是 15 秒、1 分钟或像素槽位。事件以来源时间、接收时间和稳定事件 ID 排序；来源时间相同的多笔事件仍分别保留。绘图库所需的唯一坐标只能在展示投影中生成，不能反写或覆盖原始时间。前端必须关闭点合并，缩放只改变可见范围，不得删除、覆盖或降采样业务事件。
- 周期 Bar 只能由后端基于统一 1 分钟 Bar 投影生成。固定周期以实际交易分段开盘为锚点，不跨午休、维护或夜盘间隔；日、周、月、季、年周期按品种交易日归属生成。上期所夜盘归入下一交易日，周五夜盘归入下一工作日。前端只消费后端返回的 OHLC、`state` 与 `revision`，不得再用分钟行或报价建立第二套周期状态机。
- 本地缓存按实时数据源命名空间隔离。缓存只保存从该实时数据源固定内部通道获得的数据，不改变数据来源身份。
- 报价读取、K 线 GET 和 WebSocket 首帧只读内存或本地数据库，不在实时请求热路径调用上游。
- 当一个固定时间范围没有“已完成覆盖”记录时，页面可以异步触发独立回补命令。回补只能调用当前合约所绑定实时数据源自己的 `kline` 能力；原始 K 线按真实内部通道落库，覆盖记录按实时数据源命名空间保存，随后页面重新执行本地 GET。
- 当页面在同一已知交易时段内观察到两个真实 Bar 之间存在缺口时，可以对该精确缺口执行一次 `revalidate`。精确复核只绕过粗粒度完成覆盖，不改变合约绑定、不跨来源补值；跨会话、维护、周末或其他计划休市不得触发该流程。粗粒度覆盖记录表示“该范围已向同源上游请求完成”，不是“范围内每分钟必然存在 Bar”。
- 分时与所有 K 线周期共用持续历史需求规则：用户拖动或缩放到当前本地序列左边界后，该需求在分页加载期间保持有效，不因一次加载锁而丢失；当当前已加载的完整序列仍不足以覆盖可见窗口时，也可以自动建立同一需求。程序性 `fitContent`、周期重绘和实时刷新在已有数据足以覆盖视窗时不得自行访问上游。更早数据逐页前插并保持用户可见逻辑区间；连续空窗口最多自动向前推进七天，防止在来源保留边界无限请求。
- 历史范围、分时事件数和页面累计 Bar 数不存在 48 小时、10000 分钟或 20000 点等业务上限。数据库与浏览器之间、应用与上游之间可以使用固定大小的传输页，但必须用不透明游标或连续时间窗口自动续页，直至本地游标结束或用户请求的完整范围完成；传输页大小不得表现为数据截止点。
- 同一范围、同一复核模式的并发回补必须合并为一次上游请求；重叠普通窗口先计算已完成覆盖的并集，只请求真正缺少的时间差集。成功响应即使返回零根 K 线，也要记录粗粒度覆盖，以区分已请求范围与尚未请求；若页面随后在同一交易时段内观察到具体缺口，精确 `revalidate` 仍可重新请求该子区间。网络或协议失败不得记录完成状态。
- 回补、下载和批量落库不得阻塞报价接收、当前柱生长或 WebSocket 广播；任何失败只影响过去数据的补齐状态。

## 5. 当前金十实现

`jin10_client` 是一个完整实时数据源：

- `quote` 由固定的金十官网高速价格通道与金十桌面会话补充通道组成；
- `kline` 的权威状态由 `jin10_local` 的原生快照/更新协议和官方 GZip 历史文件提供；`jin10_web` 高速价格事件先创建并生长 `provisional_quote`，原生 Bar 到达后完整校准为 `provisional_authoritative`，下一根原生 Bar 或历史确认再转为 `final`。两项能力是 `jin10_client` 的固定内部组成，不是两个可选来源；
- `10004`、`10007` 和 `10006` 只是金十通道适配器识别的协议输入；进入应用层后统一表现为 `BarEvent`，不得在通用状态机、持久化或 API 中出现协议号分支；
- 历史记录以 Unix 秒时间、`10^-6` 固定价格精度和 1 分钟周期解码，按真实内部通道落库；查询结果再映射到合约绑定的 `jin10_client` 命名空间；
- 金十当前交易日官方 GZip 文件可能在同一文件标识下继续追加。文件缓存以 manifest 的条数和结束时间作为版本；校验只要求 manifest 声明起止区间内条数精确一致，允许下载文件尾部包含声明之后追加的真实 Bar，但声明区间缺行仍然拒绝；
- 页面、REST、WebSocket 和合约路由只识别 `jin10_client`，不把 `jin10_web`、`jin10_local` 暴露为两个实时数据源。
- 直连目录当前包含 `XAUUSD.GOODS`、`XAGUSD.GOODS` 与 `USDCNH.FXCM`；`XAUCNHG` 是应用层派生观察值，不对应金十原生代码。

金十 MCP 当前全面冻结：不注册为实时数据源，不初始化，不采集报价或 K 线，也不参与过去数据补取、校对或任何运行时查询。只有用户明确决定解冻并重新评审后，`get_quote + get_kline` 才可以作为另一个完整实时数据源的两个能力组件接入。

### 5.1 沪金与沪银加权指数

`AU8888`（沪金加权）和 `AG8888`（沪银加权）是加权指数观察值，不是交易所中可下单的具体月份合约，也不同于主力连续代码。应用不自行猜测或重算加权公式，而是直接读取供应商已经发布的结构化指数：

- 实时数据源 ID 为 `tonghuashun_futures`，同花顺公开网页标识分别是 `qh_au8888` 与 `qh_ag8888`；
- `AU8888` 以人民币/克计价并保留 2 位小数；`AG8888` 以人民币/千克计价并显示整数；
- 报价涨跌按公开分时载荷中的上一结算价计算，不套用普通股票昨收语义；
- 同源分钟 K 线读取公开 `61` 周期年度文件并按请求时间窗过滤；上游未保留的更早范围返回空覆盖，不从其他来源拼接；
- 本地同花顺期货通只用于交叉确认品种代码和公开网页协议；应用运行时不读取、注入或复用该客户端的私有会话，也不要求客户端常驻。

### 5.2 具体期货合约、连续序列与市场指数

以下六项均直接读取供应商发布的结构化行情，不在应用内重算价格：

- `AU2610` 与 `AG2706` 分别是上期所沪金 2026 年 10 月、沪银 2027 年 6 月的明确月份合约，公开网页标识为 `qh_au2610` 与 `qh_ag2706`；计价单位分别是人民币/克和人民币/千克；
- `USDIND` 是美元指数观察值，公开网页标识为 `wh_USDIND`，以指数点显示 4 位小数；它不是一个可下单的美元指数期货月份合约；
- `BRN0Y` 是供应商发布的“布伦特原油连续”序列，公开网页标识为 `219_BRN0Y`，以美元/桶计价；应用不自行决定换月日或拼接合约，因此它不是交易所可下单代码；
- `SHCOMP` 映射上证指数，公开网页标识为 `zs_1A0001`；`IXIC` 映射纳斯达克综合指数，公开网页标识为 `88_IXIC`。二者都是指数点位，不代表指数成分股或可交易基金。

同花顺分时响应统一以北京时间给出当前会话时钟；分钟 K 线则保留各市场源时区。应用分别按 `Asia/Shanghai`、`America/New_York`、`Europe/London` 和 `UTC` 解释时间，再由前端按绝对时刻显示，不能把所有跨市场 K 线强行标为北京时间。报价、日内统计、最近分钟线与年度分钟线必须使用同一个公开代码，不跨来源补值。

## 6. 市场状态、连接状态与数据到达

以下三个状态必须独立管理，任何一个都不能替代另一个：

- **市场状态**：合约当前处于交易中、休市或未知，由合约交易时段及后续的节假日例外决定；
- **连接状态**：实时数据源的传输连接是否建立、断开或正在重连；
- **数据到达状态**：最近是否收到新的报价事件。

休市是正常市场状态，不等于实时数据源停滞或断线。休市期间页面保留该绑定源最后有效报价与同源图表，当前柱不再表现为持续生长，价格标记倒计时冻结为零；连接可以继续保持并等待复市。真实连接断开仍必须单独报告，不能因为当前休市而隐藏。冷启动若没有可用报价快照，只允许读取同一绑定实时数据源缓存中的最后 K 线收盘价作为“最后有效行情”展示，不得从其他来源补价。
