# 本机行情与量化存储选择

2026-10-03，总控基于同输入基准作出的实施决定；不是安装完成声明。约束仍以 [精度与持久化契约](storage-contract.md) 为准，正式切换需通过当前运行时验收。

## 按实际业务分配

| 业务 | 本次选择 | 选择依据和执行边界 |
| --- | --- | --- |
| 当前报价、正在形成的柱、已确认指标 | Rust 单写者内存状态和不可变快照 | 同进程直接读取没有 Redis 或 SQL 往返；持久提交水位与实时预览明确分开。Redis 不作为本系统内部事实来源。 |
| 精确分钟事实、修订、规范报价事件、来源配置、自选 | redb 4.3.0，原生有序键和 MVCC 事务 | 当前同数据分页、范围与事件读取表现好；事实、索引、修订门控和提交游标可以同事务提交。精确值按尾数/scale 或规范字符串无损编码，完整 u64 序号和整数纳秒不经过浮点。读取在阻塞任务/专用线程，不能阻塞网络运行时。 |
| 图表的 19 类周期与历史页 | redb 中与事实同事务维护的可修订区间聚合索引，内存缓存只作加速 | 不在每次日/周/年切换时扫描数十万分钟。按既有交易时段、DST 和交易日日历取得半开区间，再组合索引。旧 high 降低、low 提高、NULL 替换和历史修订均更新受影响节点；无法使用旧缓存时须重建或准确计算，不能返回旧版本。 |
| 大批历史研究、固定输入回测复用、导出 | 不可变 Parquet 列式快照，Arrow 批次；DuckDB 1.5.6 作为隔离的批量扫描执行器 | 列裁剪和顺序扫描适合此类工作；快照绑定一次 MVCC 输入版本。精确运算只在声明的数值范围内执行，超范围和除法交由共享 Rust 精确计算，不允许 DuckDB 的浮点除法成为账本。数据库内可变表不是本项目该层的默认表示。 |
| 原始采集帧、确定性恢复和回放 | 原生持久捕获层，保留原文、身份、顺序和接收时刻；优先采用与事实库独立的 redb 追加文件 | 与事实计算分离写入者，必须在同步提交后才确认“持久接受”。该层最终格式以小帧/大帧、批量提交和崩溃测试为门槛；原有 NATS 只作为迁移输入，默认 PubAck 不作为落盘证明。原始数据不得因固定 7 天或 10 GiB 默认上限静默淘汰。 |
| 研究权威输入、模拟结果与审计账本、AI 输入和输出 | 带版本、来源和as-of的不可变规范文件与清单；进度清单原子发布，大型批次使用列式快照 | 当前落地采用目录内同步、原子发布、内容摘要和完整性审计。此类按运行或版本读取、追加后固定的对象无需加入实时事实库的单写者竞争；相对额外Redis服务也无需网络复制或第二种持久化边界。运行状态和分页完整性仍需检验，不能因文件存在就称运行完成。AI网络工作和批量研究有独立并发限额。 |

QuestDB 是已实测且适合宽十进制在线聚合的候选，本次不作为第二份在线权威事实库：现有产品需要的固定周期查询由可修订索引直接读取，任意长扫描由列式快照承担。ClickHouse 在当前修订正确性要求下的 FINAL 分页较慢；PostgreSQL 的批量索引查询已优化，但本机读取仍包含服务和客户端边界。SQLite、RocksDB、MDBX、kdb+/q 没有相同负载的本轮实测，不声称速度胜过它们；kdb+/q 缺少可用授权运行时，成本没有作为排除理由。

## 支持选择的测量

每种编码有 649,600 条分钟事实、780,640 条事件、90 个品种、两个来源，热品种有 520,000 分钟。NULL、同戳事件、乱序修订、重复重试和全表摘要先通过，再计时。SQL 最终轮暂停开发构建，但系统和 iCloud 背景活动仍存在。redb 原生 Rust 读取与 SQL 的 Python 客户端/Docker 路径不同；结果支持本项目部署形态，不是数据库理论排名。

这也明确否定“所有查询都交给 redb 逐行扫描”。在线聚合索引尚需新的正确性和性能验收，不能用未实现的优化覆盖上表的实际慢项。窄定点扫描结果不同：DuckDB 原表 300 日聚合 Arrow p50 / p95 为 10.91 / 14.65 ms，Parquet 为 15.32 / 19.07 ms；不能从某一种数值宽度推导其他宽度结果。

redb 每 1,000 行 Immediate 整事务的宽值 bars p95 9.968 ms、events p95 8.746 ms，包含门控、编码、索引和提交，并非单独 fsync 时间。当前原始载荷和实际混合采集负载不在该数值内，另做定向验收。

原始捕获的定向实验随后完成，见 `validation/capture/directed.json`。共享库 / 独立 raw 文件的 512 B 帧持久追加 p50 / p95 分别为 8.95 / 11.54 ms 和 5.95 / 8.60 ms（各 81 次）；32 MiB 帧则为 305.77 / 342.69 ms 和 331.46 / 361.75 ms（各 9 次）。并行的每 1,000 事实整事务 p95 为 7.49 / 9.93 ms。选择独立捕获文件的依据是独立生命周期、恢复及空间策略，以及此次小帧结果；不能称大帧或事实写入全面提速。后台开发与系统活动仍存在；两模式先后运行的累计 RSS 不用于比较峰值。32 MiB 完整内容 hash 回读及收到持久回执后 SIGKILL 恢复已通过；外部生产者队列的总字节约束和完整运行时混合负载仍待验收。

基准在 [validation/storage](../work/rust-migration/validation/storage/)：`manifest.json`、四 SQL 报告、`quiet-read.json`、`redb-native.json`。同库事实/游标 MVCC、坏批回滚、重复和陈旧拒绝及进程 SIGKILL 恢复通过；这不等同物理断电、设备损坏或高可用验收。

实际旧存储只读导出随后完成：PostgreSQL 的 17 张表来自同一 repeatable-read 快照；NATS 固定范围 2723916–3189213，共 465,298 帧，保留原有缺失前缀。见 `validation/capture/legacy-export.json`。四个采集通道正文共约 1.467 GB，按正文 hash 去重后约 107.2 MB；THS 历史帧实际最大约 1.93 MB，32 MiB 是边界压力样本。决定实现捕获正文内容寻址去重：保留每次接收的全部 envelope、时间与顺序，同一 Immediate 事务写入新正文及帧引用，读回恢复原文字节；不得合并事件或丢弃正文。实现后另测真实子集的持久追加延迟、空间和崩溃恢复，再据实报告收益。

内容寻址实现已完成定向验证，`validation/capture/body-directed.json` 记录实际固定子集 5,071 帧：全部 277 个 THS 历史帧，加原序号可被 97 整除的其余帧。正文 402,627,069 字节、唯一正文 52,181,087 字节。相同 Immediate 回执条件下，THS 历史 p50/p95 从 15.969/24.061 ms 降至 9.477/13.950 ms，THS live 从 4.672/5.907 ms 降至 3.921/4.993 ms；金十变化较小。加上三个 32 MiB 边界样本后，物理 redb 文件为 872,419,328 对 268,439,552 字节；该值包括可复用页，表内持久载荷为 507,335,660 对 123,335,246 字节。完整 ProviderFrame 逐帧回读、重启、回执后 SIGKILL 恢复、v1/v2 混读、缺正文拒绝与按重建字节限制 scan 已通过。子集采用合成连续导入来源，不能据此宣称完整旧流恢复；本机背景负载仍存在，32 MiB 仅三次边界样本不作 SLO。

已经实测 `rust_decimal::MAX.checked_add(1e-28)` 返回原 MAX。受检不代表无舍入。精确有限加法和乘法使用足够宽的系数运算，允许受检的固定宽度快速路径和任意精度回退；除法、平方根、估计模型明示计算版本、精度和舍入。原始值不为计算而改写。聚合完整 volume 只在所有输入已知时提供，另返回 known sum / known count / total count。

Parquet 快照必须从同一 MVCC 读视图生成，包含 schema/计算版本、源范围、提交游标、行数和内容 hash。先写临时文件并同步，再原子发布清单和目录同步；中途失败不发布部分文件。旧快照不可被原地覆写或冒充最新。修订后生成新版本，同一运行保持其原输入；文件回收不得删除运行仍引用的版本。

DuckDB 的 DECIMAL 最多 38 位且除法返回 DOUBLE。使用 Arrow Decimal 的快速扫描前必须验证每列刻度、最大系数、聚合范围；无法证明可表示性时读取无损系数/scale列并由 Rust 计算，或返回具体不支持原因，绝不静默改变数值。新运行必须显示所用快照水位和新鲜度。

## 迁移和关闭门槛

旧 PostgreSQL、NATS 与旧安装目录保留为恢复来源。迁移建立固定来源版本/范围和行摘要，校验原始帧身份、事实、NULL、修订、配置、事件与游标；旧存储已经缺失的精度和原始帧不能声称恢复。先构建候选，再完成增量追平、停旧采集、导入已接受尾部、核对摘要和原生重启，最后切正式入口。回退也必须说明切换后新增数据的归属，不能重启旧服务后静默分叉。

安装前必须完成原生 HTTP/WS 的真实页延迟、持续采集+历史查询+回测并行负载、退出排空、重放幂等、历史修订、聚合索引重建、快照失效、数据量与磁盘增长测量。速度优化不得缩小其他 REQ 的全品种、全周期和产品验收范围。
