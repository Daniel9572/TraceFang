# 全市场与最终安装验收

总控 2026-10-03；用于 REQ-0002/3/4/5/11/12 的最终验证。执行实施、基础测试和部署由 SOL 负责，总控复核证据；不把设计条目当作通过。

## 固定对照和完整范围

先保留已知失败基线，再对当前原生版本重新跑同输入：`.mypowers/work/market-data/full-audit-2026-10-02/baseline/`。该目录有实际 SHFE 四份输入，并非全部缺失：延迟期权 710 条、标的 8 条、合约主数据 6276 条 / 23 产品、日数据 6244 条及波动率。旧 API 把 404 条未知量误记为零，该项必须修复后逐合约比较，不能因 Python 参考也有错误而保留错误。

Rust 的 `captured_710_contracts_and_expiry_analyses_match_current_python` 所缺的是 expected 导出，可从保留的原始输入和当前明确修复后的 Python 参考生成；保存生成器、输入 hash、输出 hash 及参考版本。它是固定黄金样本差异验收，不是全期权验收，也不是新的行情采集。

参考清单至少独立列出：当前 12 项目录、90 项同花顺主力合约、SHFE 主数据全部 23 产品及每份实际行情文件中的全部合约。每项记录参考身份、日期/时刻、来源、产品是否接入、精确字段是否有证据。真实月份合约、加权连续序列和主力映射不得互相替代；主力合约变化必须有生效时点和具体合约身份，不改写旧时间的身份。当前目录 12 项与参考 90 项不相等，不能只跑自选列表后称全部通过。

期权逐项核对标的、月份、到期、行权价、方向、乘数、价格/买卖盘、前结算、量、持仓及其变化、成交金额和行情时刻。未返回字段保持未知；IV、Greek、GEX 属于模型结果或证据不全的派生值，不以模型结果填补来源事实。扩展测试应覆盖真实全部产品代码，不只把 `au` 正则换一个黄金样例。其他交易所和海外客户端未取得完整参考时单列边界，不声称已经覆盖全球所有合约。

每项状态只有可解释的通过、失败、未接入、证据不足；结构有效、HTTP 成功、数据库有行各自不足以成为价格通过。不同接收时点的最新报价不能直接拿来作精确差异，应先固定同一上游报文，检验解码 → 规范事实 → 原生库 → API 的同一身份和时刻。客户界面核验另外保留真实来源与截图时刻，不以公开 API 对照冒称桌面客户端对照。

验收工具本身也须采用相同事实边界。当前 `scripts/audit_market_data.py::inspect_bars` 仍要求 `0 < low`，全市场前必须去掉通用正价限制，仅保留有限数值及 OHLC 包含关系；有特定正价约束的来源或指标单独验证。2026-10-03 客户端已直接看到合法负值价差，以及同一黄金页中 `UCMC:AUUSDO` 和 `UFXB:XAUUSD` 两个不同价格身份，见独立观察文件。不能通过缩小参考品种使错误规则看起来全部通过。

REQ-0003 用户指定的客户端品种名称是“伦敦金现”，因此 `UCMC:AUUSDO` 必须成为明确核对项，不能拿 `UFXB:XAUUSD` 的同花顺页面作为替代通过。当前 catalog 的 XAUUSD 只有 `jin10_client` 来源；`XAUUSD.GOODS` 是 `providers/jin10.rs` 的金十通道代码，不是已证实的同花顺通道。项目尚未建立两个同花顺客户端身份的独立接入证据。来源验收包需查明实际映射、上游能力和报价基准，必要时将两种客户端身份拆为独立接入/选择项。若只能取得其中一种，必须保留未接入状态并准确标识来源名称，不以同属“同花顺”掩盖差异。

2026-10-03 已核查同花顺[官方数据接口 FAQ](https://quantapi.10jqka.com.cn/gwstatic/static/ds_web/quantapi-web/help-center/faq.html)：其分钟线由快照合成，须区分采样站点与数据产品；该接口不提供逐笔，实时逐笔另属 Datafeed。因而 iFinD HTTP 能力不能直接当作期货通客户端同源证明。此边界用于要求更精确的来源身份，不能用来解释或放过本机相对自己原始帧的差异。尚未取得 AUUSDO 接入映射；没有申请账号、购买数据或发送任何凭据。

## 历史、周期和修订

旧分钟基线中 AU2610 有 2 项、USDIND 有 1 项、BRN0Y 有 25 项不一致，须逐条解释并在新事实/索引上重验。无参考的行保留“无证据”，不能算匹配；旧时间污染数据已隔离，不重新混入规范分钟事实。

19 种界面周期逐项声明可用能力。只有分钟快照的源不能制造逐笔；1 秒/分时来源不足时显示具体能力和证据范围。具有分钟证据的周期使用同一来源、范围与日历聚合，核对所有 OHLC、NULL/已知量、首末时刻、组件数和修订。至少覆盖交易日跨夜、DST、周/月/季/年、空范围、尾部尚未结束、旧极值撤回和中间分钟 NULL 更正。

同版本长历史分页无静默上限、无重复无漏，before 为排他；任意页切换不启动同步回补。回补进度/范围和内容完整性分开表示。观察页面快速切换源、品种和周期时旧响应不能覆盖新状态，首根实时柱可显示。

## 故障、时效与运行身份

在隔离目录注入原始存储故障、事实写入故障、缓冲区占满、单品种 HTTP 超时/坏响应、WebSocket 断开、批次后项非法、流 epoch 变化/缺口和强制退出。检查未确认数据、持久游标、重放幂等和错误证据；健康须准确区分已连接、已收到有效数据、新鲜、市场关闭与缺失恢复证据。停止采集后排空已接受的原始帧，再完成投影和提交；未完成就不能报告干净退出。

当前数据目录和必要日志放在 Application Support / 专用数据路径，可再生编译缓存放 Library/Caches，避免 iCloud 工作区竞争。实际路径写入发布清单，清理仅限本任务拥有的测试资源，保留旧正式数据。

发布清单包括源文件摘要、依赖锁、二进制、前端资源、数据库模式/索引/精度版本与 build ID。真实进程路径、API build ID 和静态资源必须对应同一 release。停旧采集、追平尾部、核对完整性后切换正式服务；实际重启后再验证仍运行该构建和该数据目录，不能只检查 `runtime=rust` 文本。

## 产品和性能闭环

最终通过实际正式页面复验绘图、指标图层、可见区间量分布、回放、配置模拟→进度/取消→账本→比较、同版本 AI 输入与返回。固定数据浏览器证据可证明交互，但真实来源、周期和安装版需要另外复验。

速度记录原始输入接受、同步提交、投影可见、HTTP 返回和页面显示各阶段；并行采集、长历史读取、研究/模拟和 AI 不应互相占满关键执行路径。基准结果只支持明确数据规模与负载；生产接口测量使用实际序列化和当前代码。验证增量指标及可复用索引使更新工作与受影响部分相关，而非每次 tick 重算全部历史。回放 seek 用有版本检查点和短尾重建，重复同输入 hash 一致，前视隔离仍通过。
