# 共享指标状态、模拟回测与 AI 证据

适用 REQ-0005、REQ-0008、REQ-0009、REQ-0010、REQ-0011、REQ-0012。这是本次实现设计，验证状态以工作矩阵为准。仅模拟，不增加真实交易执行。

## 当前缺口与计算归属

当前 `expertAnalysis.ts` 以浏览器浮点计算指标和收益，参数多数写死，按信号柱收盘换仓，固定单边 0.02% 摩擦，胜负不计成本。`finiteNumber(null)` 还会经 `Number(null)` 变为零。原生 `analysis/context.rs` 已使用精确行情字符串，但缺少内容版本与同版本指标，行情和外部期权分次读取会混合时点。恢复这些入口不等于完成量化功能。

采用同一 Rust 指标/策略 evaluator，供实时确认状态、回放与模拟运行调用。价格、数量、金额、费用及已知成交量保留精确十进制，禁止先转 f64 再计算账本。除法及平方根等无法有限表示的计算必须有固定精度与舍入政策，并标记计算版本；原始行情不因此被舍入。图表坐标可以近似，不能回流成为计算输入。未知值保持 null，零量是有效值。

保留策略目录现有 17 项及各自 `compositeEligible` / `backtestEligible` 边界。结构标注、风险上下文和需要外部数据的项目不得为方便回测而强行转为买卖方向。先迁移已有公式和资格，再开放参数；已有规则变动需更新版本和对照测试。

## 一个数据版本

每个快照包含 `schema_version`、`calculation_version`、品种/来源/周期、`decision_as_of`、应用序号/修订范围、输入条数、数据能力、参数以及内容 hash。hash 覆盖规范顺序的精确输入、NULL、状态、修订和参数，不能只用末根时间或当前墙钟。

确认指标只使用截止点以前已知且完成的柱，实时未完成柱是单独预览状态。事件回放以原始帧应用顺序重建，指标时钟随该顺序推进。历史查询若仅保留最终修订，运行标为“最终修订历史模拟”，不能宣称还原当时可得信息；原始事件回放才可声明对应的接收时点语义。追加未来事件不能改变已有决策；早期修订改变输入版本并从受影响处重算。

精确定位同时保留有序事件游标与时刻，不按来源时间重新排序真实处理顺序。行情时刻、原始接收时刻、日志接受时刻和播放时钟分别命名；墙钟倒退或来源乱序不能倒退应用序号。长原始日志的 seek 需使用有版本、来源范围和输入水位的不可变检查点，再顺序重放其后的片段，不能每次从保留日志首帧全量解码。检查点与 evaluator 版本不匹配时不能复用；缺少可追溯起始状态时标明预热/不完整范围，不从当前实时状态补齐旧时点。

同步采集状态的锁只用于取得不可变快照，研究计算、AI、网络和历史扫描均在锁外且有独立并发上限。增量指标缓存键含品种、来源、周期、参数、修订版本；同输入的绘图、回放、模拟和 AI 必须共享此语义，不能各自取不同历史长度后却使用相同版本名。

长历史不能用多个 READ COMMITTED 分页拼成自称同一时点的快照。回测和 AI 的规范输入从一次 MVCC 读视图取得，行情、最新报价与已提交水位属于同一事务版本；实时缓存领先的部分单列为预览。若接口只能提供分批读取，每批也必须共享同一个读视图/版本边界，且不能在等待数据库时长期占用行情锁。先提供纯 evaluator 接受不可变精确输入，存储适配待候选选定后一次接入，避免浏览器上传近似价格充当权威输入。

## 可定义的模拟配置

UI 保留现有策略选择，增加可保存的配置：时间范围、指标周期/阈值、合成入场阈值和中性退出规则、初始资金、每次目标数量、合约乘数、允许方向、费用模式与费率、单次固定费用、滑点 tick 数与 tick 大小、结算精度、期末持仓处理。输入金额/数量使用十进制字符串，周期与计数必须为有效整数，未知字段和不支持的模式拒绝。

默认规则沿用当前合成方向资格及阈值 0.2，改为收盘确认信号后，在下一根可用柱的开盘模拟成交。这消除使用收盘信息又假设已在同一收盘成交的乐观边界。默认每次一个标的单位、无加仓；费用显式显示原有 0.02% 单边默认值，滑点默认 0 tick 并标为模拟假设，用户可以修改。开盘成交不读取该柱尚未发生的最高、最低或收盘。只有 Bar 数据时，不伪造 tick 内成交顺序。

黄金默认 XAU/USD、USD/金衡盎司；加权连续指数和衍生观察值可以做价格序列实验，但界面必须明确其不是可执行合约。不能替用户猜测实际交易手续费、点值、换月或保证金。

## 成交与账本

单次成交有决策时刻、成交时刻、来源/品种、方向、数量、基础价格、滑点、成交价、费用、输入版本。买入价加不利滑点，卖出价减不利滑点；遵守 tick 大小，最终金额依声明的结算精度舍入。中性信号退出，反向先平后开，两个方向的费用都记账。没有下一可用柱的意图保持未成交。

用带符号数量 q 记录持仓，现金按 `cash -= delta_q × fill_price × multiplier + fee` 更新，权益为 `cash + q × mark_price × multiplier`。这是透明的价格序列账本，不冒充交易所保证金清算。短仓卖出现金不能作为额外杠杆能力；按配置的资金/敞口限制决定是否拒绝新仓并记录原因。默认不主动期末平仓，末价只用于未实现损益；用户选择期末结算时，清算动作及其成本必须单列为终端估值假设，不能装作之后的真实成交。

逐笔已平仓净损益包含入场和退出费用及滑点；胜率只统计净损益大于零的已平仓交易。零收益单单独统计，未平仓不混入勝负。每次运行返回完整配置、确定性 run hash、逐笔账本、现金/净值轨迹、未成交/拒绝意图、未平仓和成本汇总；详细轨迹可分页，不能因 UI 页数截断计算范围。

## 结果与比较

展示净收益、总成本、最大回撤、交易次数、净胜率、平均净盈利/亏损、持有时间、敞口、盈亏比/利润因子及同区间买入持有基准。买入持有使用同一数量与资金/成本设置、从可比较的首个成交点开始。没有亏损、没有已平仓交易或分母为零时返回 null 和原因，不能返回无穷或误导性的零。

收益率为末期权益除初始权益减一；回撤用此前净值峰值到当前净值的跌幅。年化与风险调整指标必须同时返回采样频率、样本量、日历/年化因子和无风险利率。优先使用交易日结束的净值收益；样本不足时保留非年化结果，不把分钟样本数机械套入 252，也不把短样本外推为稳定年化表现。多个配置比较须绑定相同输入版本、范围和成交政策。

实际页面验收发现，仅复制配置再查询当前事实会取得新的 cutoff，无法完成同数据比较。已完成运行应提供“用本次数据比较新配置”：以 `base_run_id` 引用已校验完整 canonical 文件和元数据，固定原来的市场输入、scope、可见性语义与截止点，不重新读取 live。费用、仓位等执行假设改变时保持同一输入，新的运行 hash 必须变化。指标参数变更需要重新计算，但独立的 `market_data_hash` 应仍标识同一原始规范输入；计算 hash 继续覆盖参数，不能为允许比较而移除参数校验。文件缺失、篡改、不完整、来源范围冲突必须明确拒绝。旧运行保持原样。

## AI 与交互

AI 只消费服务端构造的同版本输入快照和计算证据，返回时保留快照 hash/品种/来源/截止时刻/参数与模型信息。外部期权和其他市场输入保留各自 observed/published/received 时刻及不可用原因，仅在截止点已知时加入。AI 网络请求在获取快照后运行，耗时不会悄悄把新行情混入旧指标。AI 输出不是确定性指标，也不能改写原始事实或启动真实交易。

模型输入包含完整历史计算后的当前确认状态/独立预览、有效信号、参数、版本与必要的近期OHLCV及外部证据。绘图使用的1024点重复指标序列无需全部发送；完整可审计快照保留在本机。实际请求大小/耗时和可安全显示的失败类别单列，不能把超长请求失败伪装为已登录但无分析。精简展示序列不允许截断底层指标预热或改变计算结果。

请求返回时若已切换品种/来源/周期或回放位置，旧请求不能覆盖新视图；同视图内行情已更新也必须保留原分析时刻并显示其新鲜度。自动模式只对已改变的有效输入启动分析，限制并发并合并等待中的新版本，避免慢请求排队产生越来越陈旧的结果。

回测运行由显式操作触发，支持进度、取消、结果比较和重新运行；不会在每个 tick 全量重算。实时指标按实际事件增量更新，展示可以合并刷新。AI 更新策略依据测得的行情频率、指标耗时、请求耗时和费用，至少支持手动刷新与受控自动模式，不为追求视觉刷新频率每 tick 请求模型。

## 验收

固定小样本手工账本覆盖下一柱成交、跳空、不利滑点、开平和反向双费用、缺失量、零交易、未成交末信号、空头和持仓期末估值；总现金、权益和已实现/未实现损益逐项对账。参数改变必须改变结果版本；同输入重复运行结果相同；改变未来柱不能改变已发生交易和快照。实时、回放、回测在相同输入前缀取得一致指标。补充长历史增量性能、取消和并发隔离测量，以及实际页面配置→运行→账本→比较流程。
