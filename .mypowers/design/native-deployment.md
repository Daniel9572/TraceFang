## 准备与发布身份

构建目录使用 `Library/Caches/TraceFang/rust-target` 或显式配置的可再生目录；正式原始捕获、事实库、研究运行和版本快照使用 Application Support 下的持久路径，不跟随 release 目录或当前工作目录变化。保留旧正式库、原始导出、原始序号映射和旧 release。

独立候选 release 包含 Rust 二进制、前端产物、必要的 AKShare 隔离工作器及其固定依赖、来源配置和发布清单。清单记录源文件摘要、Cargo.lock/uv.lock/前端锁摘要、编译目标和构建配置、二进制与静态文件摘要、精度/聚合/目录/日历版本。配置秘密仅保存到本机受限文件，不写日志或证据清单。

构建时短暂冻结所有构建输入并比对前后源码树摘要，或从固定的源码快照构建；不能把并行修改期间生成的内嵌源码摘要当成完整产物身份。候选二进制和前端分别固定到版本目录。

最终停止旧采集前运行 `scripts/migration-space-preflight.py`：旧原件、固定PG导出、新canonical输入、新事实库、raw增量和至少4GiB余量须同时容纳，并按新事实文件16GiB上限而非理想压缩比例过关。可在全员停止编译、必需测试及运行中的debug审计完成后回收本任务可再生debug编译缓存；保留源代码、Release产物、运行证据及行情原件。清理后须重新采样，不能沿用清理前的估算。

在独立端口与独立数据路径启动候选，先关闭外部采集运行固定输入/故障/HTTP/WS/真实页面验收，再做授权范围内的真实接入影子验证。ready 必须证明正确的 build、数据路径、已验证恢复边界、原始捕获和投影状态，不只比对 `runtime=rust`。关闭市场与当前无新报价分别表达，不因周末误报所有来源在线，也不因周末阻止基础服务就绪。

全量迁移数据可通过显式只读rehearsal generation接受接口及性能验收，避免复制10GiB事实文件。该视图是已验证旧PG最终态，不是已完成原始事件回放；禁采集、禁投影和配置写，production_ready始终false。只读检查不激活generation、不写handoff边界；原始回放仍从保留的独立原始前缀构建，缺失的早期前缀明确影响预热完整性。

## 唯一数据交接边界

PG 的 repeatable-read 快照和 NATS 固定尾不是共同事务边界。原始导出已经导入统一 capture epoch，旧 seq 与 native seq 的映射独立保留。不能将 PG 最终历史直接标为这些 raw 帧重建出来的事实；原始回放永远使用独立空前缀/可信回放检查点，不读 PG 最终态作为旧时点种子。

选定候选后，停止旧采集和新的回补，等待已接受工作与旧投影排空。记录退出状态、旧投影水位/失败、连续两次稳定 raw 尾和 PG 最终快照身份。若退出不干净或未投影尾仍存在，须核对并恢复受影响输入，不能只因旧进程退出就认为 PG 完整。

当前旧Python实际代码没有可证明的逐raw事务水位：writer.stop直接取消任务，队列深度不包含正在写入的pending，生命周期还会先关闭writer再关闭providers。因此本次不能生成“应用已排空到raw尾”的声明，也不能手填尾序号。必须使用独立保留原始输入核对：停止/原PG快照/原始日志各自保留，对受影响事实和报价事件逐项核验；遗漏或更晚修订修复到新staging并保留原PG选择、raw位置和差异摘要。若最终事实含修复overlay，激活证据须明确其为PG快照与已验证raw恢复的组合，不能仍称与原PG逐字一致。未解决条目不为零时不能激活；原始事件回放始终独立从原始输入重建。

独立核对采用分阶段交接，避免“核对依赖PG快照、PG导出又要求核对已完成”的循环：`prepare-terminal-inputs` 只接受真实停止证据与明确未证明排空的诊断，固定PG和raw原件；`reconcile` 从保留raw独立投影，逐项比较并将必要修复写入新的staging，完整保留差异及原PG选择；只有实际核对完成、未解决项为零后，才生成 `independent_retained_raw_reconciliation` 确认，`raw_applied_through_legacy` 仍为None。验证与激活绑定原PG manifest、固定raw尾及映射、overlay报告与修复收据、最终事实和索引摘要，组合策略为 `retained-raw-overlay-v1`。

独立核对方法的时序必须为：停止 ≤ 固定PG快照 ≤ 核对完成 ≤ 排空确认。能够证明原服务排空的方法仍使用“排空确认后PG快照”的原规则，二者不可混用。保留停止后、导出前的首次raw尾观测，并在确认后再取两次稳定尾；三次观测须与固定raw manifest中的流身份、序号一致，以证明整个固定与修复窗口无新增输入。

旧正式服务由 `com.tracefang.local` 的launchd任务维持，已安装plist的KeepAlive与RunAtLoad均为true。停止执行器必须绑定预先检查的plist摘要、ready PID和进程启动身份，先移除该任务的自动重启注册，再确认原进程树退出、端口关闭及无复活；单独向API子进程发送终止信号不满足停止条件。原plist及停止尝试证据始终保留；进程退出只证明停止，不能证明旧投影排空。

增量导入 raw 到同一个持续 epoch 并核对所有映射、正文和 prefix。将最终静止 PG 事实导入隔离 generation，完成精确字段、NULL、元数据、事件与索引校验。激活该 generation 的同一事务写入专用 `projection_start_boundary`：固定 PG manifest/hash、capture tail 的 epoch/sequence/digest、原始映射摘要、旧停止/排空证据及验证摘要。

该边界声明 `legacy_import_authority`，不是原始帧派生证明。事实 `committed_capture` 在首个新原生帧成功投影前仍为 None；只有已验证边界可以令第一帧期望序号为 tail+1。没有该边界的空库仍必须从 sequence 1 开始，普通运行接口不能任意提升或跳过游标。启动时核对边界引用确实存在且 digest 相符，缺失/epoch 冲突须拒绝正常采集并呈现具体恢复错误。

## 正式启动、重启与回退

切换服务注册到该候选二进制与持久数据目录。原生运行不要求启动 PG/NATS 容器；旧容器是否继续保留运行与是否保留其数据分开处理，不执行卷删除。验证实际进程路径、API build ID、前端文件摘要与发布清单一致，并检查新原始帧、事实事务和页面版本继续增长。

按正常关停协议停止新工作、等待生产者、排空原始入口、投影到持久尾并关闭文件，再重启正式注册服务。核对原始尾、规范事实、自选/来源、研究结果、绘图和同版本接口；实际打开页面复验绘图、量分布、指标、回放、模拟及 AI 边界。

旧启动器目前更新失败会自动重启旧 release。该行为必须先判断新版本是否已经接受新输入：若没有，可恢复旧注册；若已经接受，先完整保留新 raw 与归属清单，并执行可验证的反向交接或以明确只读状态保留新服务，不能直接重启旧采集制造无声明的数据分叉。任何候选失败都不能删除它已经产生的正式数据。

## 已实现的候选启动器与尚待正式验收

`service.py::build_backend` 已从固定源码快照构建，使用系统缓存或显式 `CARGO_TARGET_DIR`，立即复制独立二进制并核对实际内嵌fingerprint与构建配置。候选包保留锁文件、非秘密源码归档、静态网页与binary摘要；准备失败保留候选和证据。DuckDB1.5.6固定六平台官方archive及exe摘要，在执行前核验。

原生启动、开发与停止入口不调用旧PG/NATS容器；Python只承担一次性管理、Windows监督及必要隔离工作器。macOS plist已经直接指向固定Rust binary并原子受限写入。`prepare`已在独立端口/禁采集目录实际启动固定33、核对完整ready/网页身份并正常退出；固定33实际旧库只读7051/v4接口和回放验收也已完成。35项定向兼容/准备/恢复测试通过。

`wait_until_ready`已核对build、持久路径、索引、捕获缺口与恢复证据，只读候选保持production_readyfalse。`activate_runtime`拒绝替换仍在采集的旧Python版本；首次迁移须同库只读核验真实production_terminal交接边界。失败后仅在捕获epoch/尾/digest、事实commit、路径和格式政策不变时恢复上一原生版本，否则保持停止并保留数据。不会直接自动重启旧Python采集。

正式8000仍是旧Python服务，本轮尚未注册directRust plist或执行最终交接；当前准备的33包也早于最新directplist管理代码，正式准备时须固定最新管理输入。下一步按前文停止与独立核对时序完成正式边界、安装、实际进程/路径/页面验证、正常重启及端到端计时。macOS是本轮真实本机目标；Windows原生启动兼容测试通过，实机注册、恢复与性能未验。
