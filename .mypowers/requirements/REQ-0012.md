# REQ-0012 精确性前提下的存储与响应速度

2026-10-02 用户结合「量化系统技术选型架构原则」明确要求：按项目各项业务重新选择存储，不能因为已有数据库、迁移成本或代码复杂度而沿用旧选择。在数据精确的基础上，以更快的数据响应作为所有改造与优化的首要目标。

验收必须先证明原始数值、缺失值、来源、事件顺序、修订和恢复语义正确，再比较相同工作负载和相同持久化保证下的读取延迟、查询可见性延迟、写入吞吐与恢复时间。选择应具体到实时状态、原始事件、可修订历史行情、研究分析和业务配置；说明胜过其他候选的适用条件。未实测的候选和环境差异必须显式记录，不能把厂商跑分或某一项测试的胜出称为全局最快。

保留 REQ-0011 全部 Rust 原生迁移范围和其他已确认产品契约；速度优化不能静默截断历史、丢事件、降低小数精度、混入其他来源、把未知值改成零、把落盘前确认当成已持久化，或缩小验收覆盖。

状态：按业务分层的存储选择已确定并落入 v9 实现与封装：redb 用于在线事实和可修订聚合，Parquet/Arrow 与受检 DuckDB 用于批量研究，原始捕获保留独立持久边界。共同输入的精度、事务与恢复证据及所测读写性能比较已完成；两份首 512 费用运行的逐笔 Decimal、页面与正常重启验收也已完成。用户取消新增回放测试，复用已有导入、G06 与恢复结果；取消的执行不算通过，本需求的正确性、完整性与速度验收契约不变。正式旧数据尾部接管和对账、存储激活及 8000 部署仍在进行，存储迁移与整体响应目标尚未完成。详见[当前计划](../work/fleet-20261004/current-plan.md)、[存储选择](../design/storage-selection.md)与[存储基准结果](../work/rust-migration/validation/storage/results.md)。
